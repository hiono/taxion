# 既知の制限

このページは現行 CLI の制限を示す。導入する配布物の固定値と検証結果はリリース情報で確認する。
ファイル名は既存リンクとの互換性のため保持する。

## 実行基盤

- 一般的な DAG executor。lane は固定の4本で、Task 間の依存を並列実行しない。
- 動的な lane plugin。lane の追加は binary の更新で行う。
- retry scheduler。失敗した lane や role を自動で再試行しない。
- 高度な cache。lane と gate の結果を保存して再利用しない。
- UI。すべての操作は CLI で行う。

逐次 role packet lifecycle は明示承認した READY Task と bounded review Flow が対象となる。発行済み Dispatch の採用、未来の evidence の生成、repair / re-review の追加契約承認は代替しない。保存・検証と rollback の条件は [role handoff packet](role-handoff-packets.md)を参照。

## Task 単位の集計と再契約

`workflow evaluate` は Dispatch/session 数、nano-AIU、経過時間、repair/re-review の
承認上限・消費・残量を表示する。金額上限を要求する場合、必要な usage の不明・不完全を
残量として使わない。provider/account 方針との違いは[課金ガイド](billing.md)を参照。

`resource_approval_required` はモデル応答待ちと利用量受信時の判断要求であり、完了時間の保証ではない。
外側の操作者が残工程・検証・修正・保存・回答待ちと、同じ単位・範囲の累計費用を見積もる。
`workflow extend` は現在の工程境界前に承認済み期限・正の native 上限を増やす操作で、
権限・回数・provider 枠・独立 caller 期限の上書きはしない。
停止後は同じ実行の延長ではなく、保存成果を引き継ぐ正式な後続を作る。

## report の接続

lane report と gate report は別の report である。contract gate report に lane 結果を埋め込まない。両方を別々に実行し、`executionGateOpen` と `verdict` を確認する。

## 承認の範囲

- confirmation token は確認用の digest であり、認証 token ではない。token の一致は人間の認証を意味しない。
- gate は承認、Dispatch の発行、公開を代行しない。
- publication gate は、保存済みの Task と Flow の状態だけを読む。remote の権限、認証、公開先の現在の状態は検証しない。
- 公開の承認と配送は別の操作であり、gate が `pass` でも公開要求が自動で作られるわけではない。

## legacy の扱い

- `verified-legacy` の Task は従来の検査で実行できる。bundle を要求しない。
- `invalid-or-ambiguous` の Task は修復まで拒否する。自動変換はない。
- Task の一括再承認はない。`taxion task reauthorize --task TASK_ID` は READY Task 1件の設定承認を追記し、Task 契約や state は変更しない。
- 再承認には有効で一意な immutable proposal reference が必要。既存 bundle との不一致、hash の自動 migration、承認の書換えは許可しない。

## 診断と credential

- gate report、lane report、入口拒否の診断は credential らしい値を伏せる。伏せ字の対象は既知の pattern であり、すべての秘密を検出する保証はない。
- bundle は解決済みの credential 値を保存しない。選択した設定 tuple と field の出典、その digest を残す。
- 診断に Task の全文や設定値を含めない。

## 互換性

- 未知の `bundleVersion` または `canonicalizationVersion` は `invalid` として扱う。
- 新しい承認・指示・結果・検証・延長監査を保存した store を、それを理解しない旧 binary で操作しない。
- rollback は現状を保全し、適用前の整合バックアップを別配置で使う。承認や監査を削除・置換しない。
