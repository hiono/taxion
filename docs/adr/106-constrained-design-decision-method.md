# ADR-106: 制約付き最適化による設計判断の比較方法

Date: 2026-11-20

## Status

Accepted

## Source decision

アーカイブ済み `hiono/obsolete-taxion` の設計分析資料に記録された制約付き最適化の考え方を参照します。複数候補を比較する際に再利用できる判断規則を抽出し、新Taxionの設計方法として再確立します。旧分析表、旧実装状態、Issue / PR履歴は移植しません。

## Context

複数の設計候補や実装経路を比較するとき、名称・型・構造の類似性だけで対応付けると、責務の欠落、二重の権限源、移行専用データと実行時責務の混同を見落とす可能性があります。一方、主観的な比較を繰り返すと終了条件が定まらず、判断が収束しません。

設計判断には、必須の安全条件と、コスト・速度・変更量などの最適化対象が混在します。必須条件を単一の加重スコアへ含めると、利便性や低コストによって安全性・認可・データ整合性の違反を相殺する危険があります。

## Decision

複数の設計候補・実装経路・責務配置を比較する場合は、適用可能な範囲で制約付き最適化を用いて候補を導出します。単一候補しかない判断や単純な局所変更に、数理最適化を強制しません。

### 1. 問題を責務単位へ分解する

1. 解決対象を、観測可能で検証可能な責務、不変条件、利用者要求、運用上の要求へ分解します。
2. 責務を割当可能な最小単位へ分解します。複数の要素にまたがる責務は、割当前にさらに分割します。
3. 比較候補を列挙し、各責務に対する処置を少なくとも次のように区別します。
   - `REPLACE`: 新候補が責務を代替する
   - `SPLIT`: 責務を分割し、複数候補で代替する
   - `MIGRATION_ONLY`: 既存データの読込み・変換・履歴保全に限定する
   - `RETIRE`: 要求上不要として廃止する
   - `GAP`: 代替がなく、設計または実装が必要である
4. 各割当には、型・操作・検証・永続化・状態遷移・認可境界・復旧手段など、責務の性質に応じた根拠を要求します。名称や構造の類似だけで対応を認定しません。

### 2. 必須条件をハード制約とする

認証・認可、秘密情報保護、データ整合性、人間承認、成果物の出所、二重実行防止、不可逆操作などの必須条件はハード制約とします。これらをコスト・速度・変更量などの利点で相殺できる加重和へ含めません。

評価は必要に応じて次の辞書式優先順位で行います。

1. ハード制約違反をゼロにします。
2. 必須責務の未充足をゼロにします。
3. 二重権限源、不要な旧実行依存、責務の重複を最小化します。
4. 移行コスト、運用複雑度、変更量を最小化します。
5. 同等解では、責務境界が明確で、独立して検証・テストできる解を優先します。

問題の性質に応じて評価順序を明示的に調整できます。ただし必須条件をソフト制約へ格下げしてはなりません。制約を満たす解が存在しない場合は、違反を隠して候補を採択せず、実行不能条件と不足する判断材料を記録します。

### 3. 実装状態と証拠を区別する

候補の実装状態は、少なくとも次の水準で区別します。

- `FULL`: 責務を実行する操作、不変条件の検証、永続化または必要な状態管理が確認できる
- `PARTIAL`: 一部の責務は存在するが、経路・検証・状態遷移・運用操作のいずれかが不足する
- `NONE`: 代替実装が確認できない
- `MIGRATION`: 既存データの読込み・変換・履歴保全に限定される

証拠のない割当を実装済みと扱いません。未確認事項は推測で補完せず、不確実性または追加調査項目として残します。設計上の目標経路と、ソース・テスト・実運用で確認した現在の経路を分けて記録します。

### 4. 比較の終了条件を事前に定義する

最適化を開始する前に、責務集合、候補集合、ハード制約、評価順序、必要な証拠、判断期限または停止条件を定義します。

次のいずれかに達した時点で比較を終了し、結果を記録します。

- ハード制約を満たす候補が一意に選定された。
- 複数の同等解が残り、明示した二次評価基準または人の判断で選定された。
- 実行可能解が存在せず、制約または要求の見直しが必要と判明した。
- 判断に必要な証拠が不足し、追加調査・実装・計測へ移す項目が特定された。

新しい候補・証拠・制約が結論を変え得る場合に限り再評価します。比較対象や評価基準を追加し続けること自体を目的にしません。

### 5. 人間の判断権限を維持する

最適化結果は判断を支援するものであり、要求の優先順位、必須条件の変更、リスク受容、不可逆操作の承認を自動決定しません。これらは権限を持つ人が明示的に決定します。

## Consequences

- 設計比較を、再現可能な入力・制約・評価順序・証拠に基づいて説明できます。
- 未実装・部分実装・移行専用の責務を、既存コードの存在だけで代替済みと誤認しにくくなります。
- 比較の終了条件が明確になり、主観的な比較ループを抑制できます。
- 問題定義と証拠収集に初期コストが発生するため、複数候補間の重要な設計判断に適用範囲を限定します。
- 数学的な最適解であっても、要求や候補の定義が誤っていれば結果も誤ります。問題定義と入力根拠のレビューを省略しません。

## Security and operational impact

セキュリティ・認可・秘密情報・データ整合性・人間承認に関する必須条件は、最適化のハード制約として維持します。モデルの出力や評価スコアだけで、権限拡張、リスク受容、不可逆操作の承認を行いません。入力・根拠・評価結果・人による例外判断を追跡可能に記録します。

## Alternatives considered

- **主観的な比較を反復する:** 終了条件が曖昧で、責務漏れや比較の無限化を防げないため採用しません。
- **要素名・型名の類似による一対一対応:** 責務の分割・統合、権限境界、移行専用データを表現できないため採用しません。
- **すべてを単一の加重スコアで評価する:** セキュリティ・認可等の必須条件がコストや利便性で相殺される可能性があるため採用しません。
- **すべての設計判断に数理最適化を強制する:** 単純な局所変更や候補が一つしかない判断には過剰であるため採用しません。

## Relationship to other ADRs

- ADR-100は製品目的と利用者価値を定義します。
- ADR-101は旧設計の制約を温存しない再構築原則と候補実装の評価区分を定義します。
- ADR-201はJobの責務・成果・証拠のドメイン正本を定義します。
- ADR-500は認証・認可・禁止副作用など、最適化で相殺できない安全境界を定義します。
- ADR-800は検証証拠の水準とJob完遂の受入れを定義します。
