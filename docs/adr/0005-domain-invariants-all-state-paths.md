# ADR-0005: ドメイン不変条件をすべての状態変更経路で強制する

Date: 2026-11-20

## Status

Accepted

## Source decision

アーカイブ済み `hiono/obsolete-taxion` のAccepted ADR-0079を根拠として、新TaxionのJobAggregateと状態変更経路に適用する形で再構成した。

## Context

不変条件を判定する関数が存在することと、その条件がシステム全体で守られることは同じではない。生成・変更経路だけでなく、保存、復元、外部入力、競合、再送、recoveryに迂回路があれば、不正状態が成立する。

## Decision

ドメイン不変条件は規範として定義し、状態を生成・変更・受入れ・復元するすべての適用経路で成立することを必須とする。

### 1. 規範と実装の対応

各不変条件について、対象状態、前提条件、成立条件、例外条件、強制箇所を明示する。コードはその定義を実行可能な形で表現する。判定関数の存在だけでは実装完了とみなさない。

### 2. 強制対象経路

不変条件の性質に応じて、少なくとも次の経路を評価する。

- 新規生成・初期化
- 状態遷移および関連データの更新
- Aggregate / Graph validation
- 永続化直前と永続化後の再読込み
- JSON等の外部表現からの復元
- migration、backup、recovery
- Controller / Runtimeによる実行直前の権限・予算・期限・scope再検証
- 競合、再送、重複実行、実行状態不明からの復旧

すべての不変条件に同じ検証箇所を機械的に追加しない。各条件について、どの経路が状態を変更し、どの境界で強制するかを設計上明示する。

### 3. 判定・強制・検証の区別

- 判定: 不変条件を評価する規範的な判定ロジックがある。
- 強制: 不変条件に違反する状態変更・保存・実行を成立させない。
- 検証: 正常系と違反系を含め、対象となる経路で強制されることをテストとコードレビューで確認できる。

validatorとmutation gateは役割が異なる。必要に応じて両方を設ける。復元時の検証は、過去に保存された不正状態を現在のモデルへ持ち込ませないために必要とする。

### 4. テストと証拠

- 正常条件を満たす状態変更が成功することを確認する。
- 不変条件に違反する状態変更が拒否されることを確認する。
- 拒否後に元の状態・履歴・永続データが変更されていないことを確認する。
- 不正な保存データ・外部入力・migration dataの復元が拒否されることを確認する。
- 実装上の入口と呼出し関係を調査し、未確認経路を明示する。
- テスト成功だけで未調査経路を含む全体保証を主張しない。

### 5. 適用範囲

Job、Task、RoleExecution、JobApproval、PlanningAuthorization、JobMessage、ProviderOperation、WorktreeOwnership、JobOutput、JobEvidenceおよび今後追加するドメインモデルに適用する。認証・認可、承認、秘密情報、データ整合性、二重実行防止、不可逆操作、予算、期限、成果物provenanceは必須不変条件とする。

## Consequences

ADRの論理条件、ドメイン判定、状態変更gate、Aggregate validation、テストを追跡可能にする。判定関数があっても未適用経路があれば未完了として扱う。

## Security and operational impact

安全に関する不変条件を利便性・性能・変更量で相殺しない。検証不能な場合は実行を許可しない。拒否時に部分状態を残さない。

## Alternatives considered

- 判定関数の存在を実装完了とみなす方式は、呼び出されない経路が残るため採用しない。
- 保存時validatorだけで担保する方式は、不正状態の生成を防げないため採用しない。
- Controllerごとに条件を再実装する方式は、意味の不一致を招くため採用しない。
- すべての性質を一つの巨大validatorへ集約する方式は、責務境界を曖昧にするため採用しない。

## Relationship to other ADRs

ADR-0003のJobAggregateとCommand境界、ADR-0004の認可境界、ADR-0006のJobMessage、ADR-0007のA2A、ADR-0008のWorktree lifecycleに適用する。
