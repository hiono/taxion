# ADR-0078: 制約付き最適化による設計経路の導出

Date: 2026-11-13

## Status

Accepted

## Context

複数の既存モデル・実装経路を新しい設計へ移行する際、要素名や構造の類似性を基準に比較すると、責務の欠落、二重権限源、移行専用データと実行時責務の混同を見落とす可能性がある。また、比較を主観的な納得感だけで繰り返すと、終了条件が定まらず設計判断が収束しない。

ADR-0077に基づく旧Task/Dispatch/ReviewFlow経路とJob/RoleExecution経路の対応分析では、責務を原子に分解し、候補への割当を制約付き最適化問題として定義することで、置換・分割・移行専用・廃止・未実装の区別と、実装ギャップを明示できた。

この方法は今回の移行分析に限らず、アーキテクチャ選定、責務再配置、プロトコル移行、実装方式の比較にも適用できる。

## Decision

Taxionの設計判断において、複数の設計経路・責務対応を比較する必要がある場合は、主観的な比較の反復ではなく、適用可能な範囲で制約付き最適化により候補を導出する。

### 1. 問題の定義

1. 解決対象を、観測可能で検証可能な責務・不変条件・運用上の要求に分解する。
2. 責務を、割当可能な最小単位（責務原子）へ分解する。複数の要素にまたがる責務は、割当前にさらに分割する。
3. 実装候補・設計候補を列挙し、各責務原子に対する処置として、少なくとも次を区別する。
   - `REPLACE`: 新候補が責務を代替する
   - `SPLIT`: 責務を分割し、複数候補で代替する
   - `MIGRATION_ONLY`: 既存データの読込み・変換・履歴保全に限定する
   - `RETIRE`: 要求上不要として廃止する
   - `GAP`: 代替がなく、実装または設計が必要である
4. 各割当候補には、型・操作・検証・永続化・状態遷移・認可境界・復旧手段など、責務の性質に応じた根拠を要求する。名称や構造の類似だけで対応を認定しない。

### 2. 制約と最適化

割当変数を二値変数として定義し、各責務原子に対して処置が一意になる制約を置く。分割が必要な場合は、原子を分割してから割り当てる。

認証・認可、秘密情報保護、データ整合性、承認、成果物の出所、二重実行防止、不可逆操作などの必須条件はハード制約とする。これらを、コスト・速度・変更量などの利点で相殺できる加重和に含めない。

目的関数は、必要に応じて次の辞書式優先順位で評価する。

1. ハード制約違反をゼロにする。
2. 必須責務の未充足をゼロにする。
3. 二重権限源、不要な旧実行依存、責務の重複を最小化する。
4. 移行コスト、運用複雑度、変更量を最小化する。
5. 同等解では、責務境界が明確で、独立して検証・テストできる解を優先する。

この優先順位は問題の性質に応じて明示的に調整できる。ただし、必須条件をソフト制約へ格下げしてはならない。制約を満たす解が存在しない場合は、制約違反を隠して候補を採択せず、実行不能条件と不足する判断材料を報告する。

### 3. 証拠と不確実性

候補の実装状態は、少なくとも次の水準で区別する。

- `FULL`: 責務を実行する操作、不変条件の検証、永続化または必要な状態管理が確認できる
- `PARTIAL`: 一部の責務は存在するが、経路・検証・状態遷移・運用操作のいずれかが不足する
- `NONE`: 代替実装が確認できない
- `MIGRATION`: 既存データの読込み・変換・履歴保全に限定される

証拠のない割当を実装済みと扱わない。未確認事項は推測で補完せず、不確実性または追加調査項目として残す。設計上の目標経路と、ソース・テスト・実運用で確認した現在の経路を分けて記録する。

### 4. 終了条件と判断記録

最適化を開始する前に、責務集合、候補集合、ハード制約、評価順序、必要な証拠、判断期限または停止条件を定義する。

次のいずれかに達した時点で比較を終了し、結果を記録する。

- ハード制約を満たす候補が一意に選定された。
- 複数の同等解が残り、明示した二次評価基準または人の判断で選定された。
- 実行可能解が存在せず、制約または要求の見直しが必要と判明した。
- 判断に必要な証拠が不足し、追加調査・実装・計測へ移すべき項目が特定された。

比較対象や重みを追加し続けること自体を目的にしない。新しい候補・証拠・制約が結論を変え得る場合に限り再評価する。最適化結果は判断を支援するものであり、要求の優先順位やリスク受容を自動決定するものではない。必須条件の変更やリスク受容は、権限を持つ人が明示的に決定する。

## Alternatives considered

- **主観的な比較を反復する:** 終了条件が曖昧で、責務漏れや比較の無限化を防げないため採用しない。
- **要素名・型名の類似による一対一対応:** 責務の分割・統合、権限境界、移行専用データを表現できないため採用しない。
- **すべてを単一の加重スコアで評価する:** セキュリティ・認可等の必須条件がコストや利便性で相殺される可能性があるため、ハード制約と辞書式評価を採用する。
- **すべての設計判断に数理最適化を強制する:** 候補が一つしかない判断や、単純な局所変更には過剰であるため採用しない。複数候補間の責務・制約・トレードオフがある場合に適用する。

## Consequences

- 設計比較は、再現可能な入力・制約・評価順序・証拠に基づいて説明できる。
- 未実装・部分実装・移行専用の責務を、既存コードの存在だけで代替済みと誤認しにくくなる。
- 比較の終了条件が明確になり、主観的な比較ループを抑制できる。
- 問題定義と証拠収集に初期コストが発生する。適用範囲を複数候補間の重要な設計判断に限定する。
- 数学的な最適解が出ても、要求や候補の定義が誤っていれば結果も誤る。問題定義と入力根拠のレビューを省略しない。

## Security and operational impact

セキュリティ・認可・秘密情報・データ整合性・人間承認に関する必須条件は、最適化のハード制約として維持する。モデルの出力や評価スコアだけで、権限拡張、リスク受容、不可逆操作の承認を行わない。入力・根拠・評価結果・人による例外判断を追跡可能に記録する。

## Compatibility

本ADRは設計判断の導出方法を定めるものであり、既存の実行プロトコル、保存形式、利用者向けインターフェースの互換性要件を追加しない。既存の設計・データは、必要な責務と証拠に基づいて評価する。

## Status

Accepted. The method was applied to the old Task/Dispatch/ReviewFlow and Job/RoleExecution mapping in [job-graph-mapping-analysis.md](../job-graph-mapping-analysis.md). This ADR standardizes the method for future applicable design decisions; it does not claim that every future design decision must use mathematical optimization.
