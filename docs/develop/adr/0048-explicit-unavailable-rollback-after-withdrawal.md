# ADR-0048: 旧配布物の撤回後に戻し先なしを明示する

## 状態

採用。ADR-0044 の戻し先必須の契約に、撤回後の明示的な例外を追加する。

## 背景

公開履歴を更新しても、旧バイナリ内のリビジョンは変わらない。履歴更新後のタグに旧配布物を対応付け直すと、配布元の証明が一致しなくなる。旧版の配布ファイルを差し替えず撤回した結果、利用可能な戻し先がなくなった。

## 決定

v0.7.15 の配布時だけ、workflow が `--rollback-unavailable prior-distributions-withdrawn` を指定する。配布情報は schema 3、`rollbackVersion: ""`、`rollbackPlatforms: []`、`rollbackUnavailableReason: "prior-distributions-withdrawn"` とする。v0.7.15 以降の検証器はこの組合せだけを受け入れ、理由の欠落、未知の理由、対象版・環境との併記を拒否する。検証結果にも理由を返す。

配布処理は公開済みの正式版一覧を取得し、現行版より古い対応バイナリ版が残っていればこの例外を拒否する。API の失敗はそのまま失敗とし、撤回を推定しない。通常の配布では schema 2 と公開済みの戻し先を引き続き要求する。現行版の archive、実行ファイル、配布情報の pin、リビジョン、CI、配置先の検証は緩めない。

各環境の smoke は戻し先の切替を成功とせず、利用不能として記録する。同じ固定版の再導入、選択解除、削除、出自検証と保存状態の不変性は検査する。snapshot は戻し先の検査対象外とする。通常の版の戻し先は現行 manifest から選び、撤回済みの固定版を参照し続けない。

## 移行と制約

旧実行ファイルは schema 3 を読めない。公開済みの新しい版と CI の成功を確認し、実行中の処理を停止して保存状態と設定を保護したうえで、新しい manifest pin と実行ファイルのパスを再承認する。既存 policy の自動更新や保存形式の変換は行わない。

新しい正式版には旧版への戻し先がない。障害時は同じ検証済み固定版の再導入か無効化を行い、必要なら新しい修正版を待つ。store、承認、期限、予算は巻き戻さない。将来の版は、新しい公開済み対応版を通常の戻し先として使用する。

履歴更新と配布物の撤回だけでは、GitHub 管理の参照・キャッシュや第三者の複製の消去は保証できない。詳細な消去依頼と復旧用バックアップは非公開で保持し、公開文書に秘密情報や対象の原文を記載しない。
