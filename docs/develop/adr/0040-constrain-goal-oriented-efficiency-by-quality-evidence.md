# 40. ゴール指向の効率評価を品質証拠で制約する

Date: 2026-10-17

## Status

Accepted

## Context

Reviewer の追加確認、Planner の再質問、各担当の調査は、担当単体の慎重さを増しても最終成果の品質を改善するとは限らない。一方、質問数や token 数を直接減点すると、必要な確認まで省く誘因になる。v0.3.1 では mise の更新案内を公開後に補正しており、コードだけを完了とみなす不備もあった。

ユーザーは Taxion の運用で、細かな設定確認やロール間の不要な往復が大量に発生したと報告した。今回の方針は、各担当が慎重さや活動量を増やすことを優先し、最終成果への到達を妨げる問題に対処する。質問数や通信量を減らすだけで正解率が上がるとは断定せず、改善効果は別に測定する。

## Decision

最終成果、正確性と安全性、費用の順で判断する共通方針と、Planner・Coder・Reviewer・外側の操作者それぞれの責務を接続する。共通原稿は ready、相談・計画、標準／カスタム role prompt を通る runtime・workflow・ACP で再利用する。SDK の system prompt と config hash は変わるため、旧 session の hash を新しいものへ書き換えない。取消専用接続は変更しない。

質問前に既存情報、情報不足の具体的損失、仮定の修正可能性、期待する改善と費用を判断する。必要な質問をまとめ、安全に進められる範囲は進める。追加調査・再レビューは未達条件、新証拠、条件変更、重大なリスクに結び付ける。承認・予算・同一成果物・独立性は省略しない。

Planner は安全で修正可能な既定案を使い、細部を一件ずつ質問に変えない。Coder は承認範囲内の通常の実装判断を進め、成果と証拠をまとめて引き継ぐ。Reviewer は acceptance 外の好みや任意の改善だけで修正・再レビューを発生させず、必要なら `workReport` に非blocking の助言を残す。実際の欠陥や未達条件を、費用削減のため任意扱いにはしない。外側の操作者も、結論を変えない進捗確認や再帰的な承認を追加しない。

実装と関連文書を一つの成果物として扱う。新しい request の計画には、host が文書整合の acceptance を表示前に追加し、Human が確認した契約へ保存する。ready でも同じ criterion を手動契約へ含めるよう指示する。既存の全件 PASS・証拠参照・同一 target 検査を再利用し、文書 criterion が FAIL・欠落・証拠なしなら承認しない。無関係な文書の全件再検証は求めない。

`workflow evaluate --id ID` は保存済み graph を読取り専用で評価する。完了した独立同一 target レビューと文書 criterion がある場合のみ `RECORDED_PASS`、それ以外は `UNMET` とする。`--require-quality` は未達を非zero終了にし、操作者の公開前確認へ接続する。これは外部の `gh release` を遮断する仕組みでも、semantic な真偽を自動証明する仕組みでもない。既存契約を遡及変更せず、旧 Flow の評価は criterion 欠落を明示する。

評価は加算得点や学習時の報酬関数にしない。保存済み Dispatch・instruction hash・成果 SHA、修正回数、input/output token、経過時間、記録済み実行観測を出す。token は全 Dispatch に保存された call 単位の内訳が揃う場合だけ合計し、cache 内訳を加算しない。欠損・部分応答単位・重複識別子・overflow は合計を null とする。provider の課金記録との照合ではない。集計は当該 Flow の Dispatch のみで、Planner・前の Flow・外側の agent の費用を含まない。`costComparisonEligible` は保存品質条件上の資格であり、利用量の完備や比較条件の同等性は別に確認する。

ゴール達成・正確性・効率性・情報価値・連携効率・リスク管理の六軸を評価対象とするが、保存 approval は参照解との一致や重大欠陥の見逃し率を測定したことにはならない。質問の価値、不要通信、費用改善には同一課題・比較可能な条件・独立した正解判定が必要で、未測定をゼロや成功へ変換しない。実モデル比較は別の予算・期限承認後に限る。

## Consequences

既存の承認・レビュー機構を使い、品質未達を低コストで相殺しない評価結果を得られる。新しい常設ロール、汎用報酬基盤、schema の遡及移行は追加しない。操作 skill は原稿変更に合わせて 1.3.0 とし、旧管理ファイルの明示更新を要求する。

手動契約への criterion の追加、意味上の文書整合、公開直前の候補照合は操作者と独立レビューの責務も残る。評価コマンドは保存証拠の確認であり、現在の Git・認証・公開権限を再検証しない。実モデルでの改善効果、質問や重複通信の完全な自動分類、成功率・見逃し率の実測は [#90](https://github.com/hiono/taxion/issues/90) の未完了条件として保持する。
