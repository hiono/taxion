# 0053: 承認した工程計画を元の全体期限から制御する

## 状態

採用。Issue #189。配布版への収録と実モデルでの運用改善の確認は、実装の検証とは別に扱う。

## 背景

セッションのソフト上限は役割別の資源予約ではない。実装担当が全体期限まで動くと、検証と独立レビューには進めない。説明の修正だけでも、プロンプト上の注意だけでも、この実行上の問題は解消しない。

## 決定

既存の Task と課金契約を変更せず、Flow 開始時に任意の `stageBudget` を承認する。読取り専用の `workflow plan` が、要求・Task・設定・見積もり結果をハッシュ化する。利用者が計画を承認してから `stagePlanHash` を指定して開始する。開始によって生成した計画は最初の発行監査に固定し、正規化・旧形式の読込みと更新の両方で照合する。削除による従来動作への復帰も拒否する。

時間の見積もりは固定比率にしない。同じリポジトリ・検証コマンドの成功記録を直近20件まで使い、保守的な初期値と20%の余裕を置いた観測値の大きい方を提案する。初期値と明示指定は根拠に残す。観測時間は準備と待機を含み、モデル内部の作業時間とは呼ばない。

各役割の提出期限は、最初の全体期限から、その後の必須検証・レビュー・許可済み修正の予定時間を引いて求める。早く完了した工程の時間は後の工程で使える。実装作業が後続工程の予定時間に達したら停止する。提出を受けた後の検証には、その検証の枠だけを与える。起動時・送信時・イベント監視・ツール許可・管理下の Git 更新・結果受理の各経路で適用する。

課金の残額枠は、承認済みの正の全体 `nano-AIU` 上限があり、完全な同一設定の保存使用量か明示見積もりがある場合に限る。正の全体上限があるのに必要な役割の見積もりがなければ、計画を拒否する。予約をゼロにして実装担当へ全額を渡す動作にはしない。提供元停止方式に新しい残量照会を追加せず、未見積もりを無料扱いにしない。クレジットの役割別ソフト上限は実行設定と照合し、共通上限で黙って置き換えない。

工程の開始・提出・検証・受理の時刻と適用上限は既存の追記専用の予算監査へ残す。`workflow budget` はそれを読取り専用で表示する。停止後は残る受入れ条件と保存成果を示し、計画付き後続 Flow には実行条件を変える理由と保存成果の採否を要求する。新しい承認や利用額は自動発行しない。

## 制約と旧版へ戻す手順

既存の計画なし Flow と `request` の承認は遡及変更しない。これらには工程予約がないと明示する。旧 Flow への工程計画の後付けも拒否する。

工程見積もりは完了保証ではなく、クレジットの予約でもない。使用量は報告後に監視するため、報告前の超過は防げない。イベント監視中の期限は制御できるが、監視プロセスの異常終了中は提供元の実行を能動停止できない。再接続時には元の期限を照合し、停止証拠の回収前に別の実行を開始しない。

利用額の自動配分には十分な保存実績が必要で、初回の利用額見積もりまで自動生成するものではない。実績がない場合は、正の利用額上限に対する各役割の見積もりを明示承認するか、既存の課金契約に沿った別の実行方針を承認する。計画の拒否を避けるために、課金方式や上限を自動変更しない。

`STAGE_OBSERVED` と `stagePlan` を含む状態を旧版で更新しない。旧版へ戻す場合は、現状のデータベースと作業場所を保持し、更新前のバックアップを別配置で使う。管理スキルの更新には従来どおり明示許可が必要で、版が同じでも操作契約のハッシュを確認する。

## 検証

2026-10-26 に、偽時刻の境界、同一ハッシュ承認、計画改変の拒否、役割別上限の一致、停止時の部分成果保全、合成の実装・検証・修正・独立レビューを確認した。工程期限そのものによる監視停止、期限後の直接提出の拒否、検証の時間切れについても、全体期限より前に停止し、部分 tree を保存することを確認した。工程監査には、検証の開始・終了時刻と時間切れの理由が残る。

次の検証はすべて成功した。race 検証は変更した工程制御・案内・保存経路に対象を絞っており、全テストの race 検証ではない。

```sh
go build ./...
go vet ./...
go test ./... -count=1 -timeout 15m
go test -race ./internal/core ./internal/store ./internal/runtime/controller ./cmd/taxion \
  -run 'Test(Stage|Planned|Ready|Completion|UserGuideCold|UsageGroups|Workspace|Normalized|Provider|RunReviewFlowFullRepair)' \
  -count=1 -timeout 10m
go generate ./cmd/taxion
git diff --check
```

独立したコードレビューで、利用額の見積もり不足をゼロ予約として扱う問題を検出した。必須役割の見積もりがなければ計画と開始を拒否するよう修正し、回帰テストと再レビューで確認した。提供元停止方式には、この条件を理由とする残量照会や利用額入力を追加していない。

配布版への収録と実モデル試験は未実施。実モデルでの完了率や費用削減は別途承認した試験が必要であり、合成試験からは主張しない。Issue #189 の運用上の効果確認は、その試験まで残す。
