# ADR-0001: 製品目的 — 人間の曖昧な思考を継続可能な協調作業へ昇華する

Date: 2026-11-20

## Status

Accepted

## Source decision

アーカイブ済み hiono/obsolete-taxion の redesign/job-centered-role-collaboration branch にある旧ADR-0088を原典とする（blob c7b1dc8407994da033fd3bee380cb606bc199025）。本ADRは原典の製品目的を新しいリポジトリの設計判断として再確立するものであり、旧Git履歴を引き継ぐものではない。

## Context

人間が製品やソフトウェアを作ろうとするとき、最初から要求・仕様・実装手順が明確になっているとは限りません。断片的なアイデア、実現したい状態、違和感、未整理の制約、まだ言葉になっていない判断が混在します。

一度の指示へ圧縮してCoding Agentへ渡すだけでは、実装が意図と異なる方向へ進んだ場合に、当初の目的、過去の判断、未解決の問い、変更された前提を再構成して作業を正しい方向へ戻すことが困難です。単なる指示生成では、思考の変化と作業の継続性を支えられません。

## Decision

**Taxionは、人間の曖昧な思考を対話によって整理し、実行可能な計画・指示へ昇華させ、マルチエージェントの協調とガードレールによって、人間が意図した製品を作り上げることを支援します。**

### 1. 人間の思考を出発点とする

- 入力時点で要求や仕様が完全に定義されていることを前提にしません。
- 断片的な考え、曖昧な希望、疑問、違和感を対話の出発点として扱います。
- 質問、言い換え、整理、要約、選択肢の提示を通じて、目的・制約・受入条件を明確にします。
- 不確実性や未決事項を、確定した事実や利用者の承認と混同しません。
- 人間の意図をAIが一方的に置き換えず、判断や承認が必要な境界を人間に残します。

### 2. 思考を実行可能な作業へ昇華する

- 整理した目的と制約を、実行可能な計画・指示・成果条件へ変換します。
- 作業はJobを継続単位として保持し、必要な分解・担当・依存関係をJobの範囲内で管理します。
- 計画は固定された一度限りの指示ではなく、新しい情報や成果に応じて明示的に見直せるものとします。
- 計画・指示・実行権限・承認を同一視しません。会話や提案だけで実行権限を拡張しません。

### 3. マルチエージェント協調にガードレールを組み込む

- 複数のAgent / Roleが、それぞれの担当と能力に応じて調査、計画、実装、レビュー、修正を協調して進められるようにします。
- 固定された工程順序や単一の指示形式だけに協調を依存させません。
- 情報不足は、必要な質問と回答、仮定の明示、部分的な作業によって解消します。
- ControllerはJobの同一性、承認、対象・資源境界、禁止副作用、認証・認可、データ整合性および実行状態を強制します。
- Agentの判断の自由と、人間が保持する承認権限・安全境界を両立させます。

### 4. 作業と判断を永続化し、再開可能にする

- Jobに関係する目的、計画、問いと回答、判断、担当、実行状態、成果、証拠を、後から参照できる形で保存します。
- 保存情報を作業の再開、意図とのずれの発見、判断の再確認、修正方向の把握に利用できるようにします。
- 中断後も同じJobの文脈と確定済みの事実を再取得し、未確定事項や不明な実行結果を確定済みとして扱わずに続行できるようにします。
- 情報の正本、履歴、検証証拠を区別し、同じ事実を複数の独立した正本へ重複保存しません。
- 過去の情報を無条件に現在の権限や仕様として再利用しません。現在のJob、承認、出所、状態を再検証します。

### 5. 製品の完成を評価基準とする

変更は、内部APIやAgent機能の追加だけでは評価しません。利用者が自分の意図を整理し、計画を作り、Agentと協調し、成果を確認し、必要な修正を行い、Jobを完遂できる能力が改善するかで評価します。

実用上の評価対象には、少なくとも次を含めます。

- 曖昧な依頼から目的・制約・受入条件を整理できること。
- 計画と実装のずれを発見し、元の意図へ戻せること。
- Role間の質問・回答・委譲・レビュー・修正が同じJobの文脈でつながること。
- 中断後に、保存された判断と作業状態を用いて同じJobを再開できること。
- 人間が判断・承認・介入でき、安全性とデータ整合性を維持したまま成果を完成できること。

### 6. Taxion自身を再構築対象とする

Taxion自身の再構築を、製品理念を検証する実利用シナリオとして扱います。既存ドキュメントや実装を無条件に引き継がず、原本と判断の来歴を確認し、現行の製品目的に必要な設計判断を整理します。そのうえで、責務分離とYAGNIを適用し、必要な機能と不変条件からコードを再構成します。

- 既存ADRの判断根拠・原本・後続判断との関係を確認し、現行の正本を再構成します。
- 古い設計の制約、不要な抽象化、互換性だけの経路、重複した責務を温存しません。
- 実際のJob完遂に必要な最小のモデルと境界から構築します。
- Clean ArchitectureやYAGNIを形式的制約にせず、責務分離と単純さを実現するために適用します。
- 実際の利用シナリオで検証し、複雑さそのものを理由に汎用機能を追加しません。

## Non-goals

- 一度の指示を高精度に生成するだけのツールにはしません。
- 作業履歴を保存するだけの記録ツールにはしません。
- Agentへ全面的に自律実行を委ね、人間の意図・承認・安全境界を失わせません。
- 既存の全設計・全履歴を互換性のためだけに維持しません。

## Consequences

- Taxionの最上位の設計判断は、製品目的と利用者価値に照らして解釈します。
- Job、Role、JobMessage、JobAggregate、Provider lifecycle、権限境界、証拠の具体的な契約は下位ADRで定義します。本ADRは内部構造や物理スキーマを固定しません。
- 対話・計画・実行・レビュー・修正・再開を、同じJobの目的と履歴へ結び付けます。
- DBへの保存は製品価値の一部ですが、独立したMemory subsystemや二重の正本を追加する根拠にはしません。
- 実装の複雑さ、Agent数、抽象化の数、保存する情報量を、それ自体で製品価値とみなしません。

## Security and operational impact

人間の意図を整理する対話と、実行権限・承認を分離します。自然言語本文、Agentの提案、保存された回答、過去の判断だけで認証・認可・承認を成立させません。Jobの対象境界、禁止副作用、秘密情報保護、Provider実行状態、データ整合性は下位ADRの規範に従い、曖昧さを理由に安全境界を緩和しません。

作業の再開では、保存済みの事実と現在の外部状態を区別します。Providerの実行結果や停止状態が不明な場合は不明として保持し、未確認の成功、権限、成果を推定しません。

## Relationship to other ADRs

- ADR-0002は、本ADRの製品目的を実現するための全体再構築原則を定義します。
- Job、Role、JobMessage、認可、永続化、Provider、Worktree、証拠、復旧の具体的な決定は、本ADRとADR-0002に適合する下位ADRで定義します。
- 本ADRは既存の個別設計判断を一括して置換しません。具体的な判断の変更は、対象を限定した後続ADRで明示します。
