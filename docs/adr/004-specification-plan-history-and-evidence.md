# ADR-004: 現行仕様・開発計画・履歴・検証証拠の正本を分離する

Date: 2026-11-20

## Status

Accepted

## Context

設計判断、現行仕様、計画、作業履歴、CI結果は意味と更新頻度が異なります。同じ文書へ蓄積すると、過去の状態や検証結果を現HEADの仕様・品質と誤認します。

## Decision

情報の種類ごとに正本と記録先を分離します。

| 情報 | 正本・保存先 |
|---|---|
| 設計判断 | RepositoryのADR |
| 現行仕様・操作方法 | Repositoryの現行ドキュメント |
| 設計・実装の変更履歴 | Git commit |
| TODO・ロードマップ・開発計画・実験計画 | 既存のDropbox文書 |
| 作業経過・未達事項 | GitHub Issue / PR |
| 変更差分・レビュー | GitHub Pull Request |
| CI・配布・テスト結果 | GitHub Actions等の実行記録 |

Repositoryのドキュメントは現HEADのコードと設計に一致させます。開発履歴、作業ログ、過去HEADの検証結果を現行仕様へ蓄積しません。

計画情報は既存のDropbox文書で管理します。作業開始時に所在、アクセス可能性、更新時点を確認し、取得できない情報は未確認として扱います。既存のDropboxフォルダー、文書名、保存先、参照先は明示的な指示なしに変更しません。

現行の開発対象である `hiono/taxion` では、Issue本文に問題・目的・完了条件を記録し、Issueコメントに利用者の指摘・判断・開発エージェントへの補正・対応結果を時系列で追記します。過去のコメントは編集・削除せず、訂正や追加情報は新しいコメントとして残します。PR本文には変更の概要と検証範囲を記録します。Issueコメントの追加・更新を一律に禁止しません。

Issueは独立して完了判定できる一つの問題・疑問・変更単位とします。新しい疑問や軌道修正で対象・目的・完了条件が変わる場合は新しいIssueを作成し、関連Issueを相互参照します。別の課題を既存Issueへ継ぎ足しません。同じ作業単位の指摘・判断・対応履歴は、そのIssueのコメントへ時系列で追記します。

作業単位が終了したIssueは、結果を問わずクローズします。クローズ前の最終コメントに、結果（成功・失敗・中止・重複・方針変更・対応見送り等）、理由、成果または未達事項、関連する後続Issueを記録します。Issueのクローズ状態は作業単位の終了を示し、成功を意味しません。GitHub標準のClose reasonは実際の結果に合う場合に使用し、標準選択肢で表現できない結果は最終コメントに明記します。

アーカイブ済みの `hiono/obsolete-taxion` と `hiono/obsolete-taxion-poc` は読み取り専用とし、Issue・コメント・PRを含む書き込みを行いません。この制限を現行Repositoryへ適用しません。

Issue / PRには対象HEAD、実施内容、検査結果、未確認事項を記録します。CI結果は実際に検証した完全なHEAD SHAとRun IDに対応付けます。

## Consequences

現行仕様、可変計画、変更履歴、作業経過、実行証拠の責務が分離されます。過去の検証結果を現HEADの保証として扱いません。

## Relationship to other ADRs

ADR-000は文書体系と記述原則を定義します。本ADRは情報の正本と記録先を定義します。
