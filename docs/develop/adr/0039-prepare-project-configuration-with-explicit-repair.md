# 39. 初期設定を init にまとめ、診断と明示的な修復を分ける

Date: 2026-10-17

## Status

Accepted

## Context

v0.2.0 の init は DB だけを作成する。実利用では設定ファイル不足、Git 除外不足、既に初期化済みという応答を往復し、利用者が YAML を手書きするまで診断へ進めなかった。開発環境の上位 directory と実際の repository が分かれる構成では、設定の cwd 基点と DB の Git root 基点の違いも混乱を招いた。

## Decision

init は既存設定と Git remote を読み、不足項目の入力、変更案の表示、確認後の設定・Git 除外・DB 初期化までを行う。doctor は読取り専用を維持し、doctor fix は同じ設定準備処理を使って明示的に修復する。fix は DB を初期化しない。

Project 設定の基点を Git 作業ツリールートに揃える。Git 外は cwd とし、明示 store は DB の配置だけを変更する。cwd に旧サブディレクトリ設定がある場合は手動移行を求め、自動で無視・移動・統合しない。ADR-0032 の設定探索を変更しない判断は、この追加判断で改訂する。

Global・Project・対応環境変数の優先順位は維持する。既存値の置換は設定元の明示編集に任せる。複数 remote、host から特定できない provider、account・契約・承認参照は入力を求める。非対話時は不足を一覧にし、--set と --yes による適用を要求する。

Git 除外不足だけは修復準備中に観測できるが、追跡済み設定と symlink は拒否する。通常実行の Git policy は緩和しない。既存の有効な exclude は尊重し、不足規則は確認後に追記する。設定は private permissions、一時ファイルと置換、設定処理の排他で保存する。途中失敗では保存済みの対象と未実施の段階を区別し、再実行で補う。

補完は実際の CLI help から生成した bash 定義を同梱する。補完実行時には設定・DB・外部コマンドを必要としない。定義の生成は隔離した環境で行い、回帰で実装とのずれを検出する。CLI framework 全体の置換や他 shell 対応は今回行わない。

help は目的別にコマンドを分類し、ready は状況と操作・承認境界の対応から具体例へ進む。分類名を新しいコマンドにせず、既存のコマンド・option・JSON schema を維持する。help の見出しはコマンド行と異なる書式にし、補完の再生成結果が変わらないことを照合する。分類で一覧を探す範囲は絞れるが、全文の token 削減や実 LLM の誤操作率改善は実測していない。

評価では既存の92コマンド行を説明も含めて保持し、12分類、分類ごとに3〜20行へ整理した。ready の JSON 例3件と生成済み bash 補完は変更していない。見出しと状況別案内で全文量は増えるため、目的別に参照するための変更として採択する。各コマンドの FlagSet を独自表示に置き換える案は、構文・補完生成への影響を広げるため今回採用しない。

## Consequences

利用者は init を入口に YAML の手書きを避けられる。一方、設定の準備だけで認証・契約資格・社内資料の送信許可・Task や予算の承認は成立しない。初期設定と補完はモデルを呼ばない。秘密値は入力しないものとし、既知の credential 形式も拒否するが、未知の秘密の不存在は保証しない。

既存のサブディレクトリ設定は手動移行が必要になる。処理中の強制終了で setup.lock が残る場合は、所有処理の停止を確認して lock だけを除去する。GitLab 実環境受入れ、モデルの実ロード、公開 tag の導入は、隔離 fixture による初期設定の成功とは別に扱う。
