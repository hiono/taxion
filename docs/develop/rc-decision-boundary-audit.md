# RC の反復と判断境界の監査記録

## 対象と確認方法

2026-11-05、公開されている `v0.7.21-rc.1`〜`rc.16` の全16版を、
Issue・PR の本文と議論、関連 ADR、タグのソース履歴へ対応付けた。
通常レビューの後続障害は、正式版 `v0.7.23` の PR #263 と
[再現・検証記録](normal-reviewer-handoff-validation.md)まで比較した。
一部の復旧事例だけを選んで RC の反復全体を説明する方法は採らなかった。

読取り専用で取得した公開記録は Issue 159件、PR 104件、議論コメント397件、
Release 28件。RC を直接参照する31件とその関連記録49件を抽出し、
ソース履歴で特定した追加 PR も確認した。49件という抽出数は監査完了の証明ではなく、
本文・議論の照合と全16タグの変更履歴を組み合わせた調査範囲を示す。
対象外の Issue も索引には含むが、全263件を一件ずつコード監査したとの主張ではない。

各 RC のソースは公開タグを解決し、`v0.7.20` から `v0.7.21` までの変更履歴と照合した。
RC7 のレビュー生成コードが出力 commit を `baselineSha` と `targetSha` に使い、
確定全変更パスを渡すこともタグのソースで確認した。
今回の不具合の再現は既存の `v0.7.22` 合成試験を参照し、全 RC の実行を再現したとはしない。
運用機の原本、製品コード、実サービスの session・利用量は取得・公開していない。
運用側の報告、開発側の合成確認、公開処理の成功を区別する。

## 反復から確認できる不足

**契約方針がなかったことだけでは説明できない。**
ADR-0055 は初回・修正・後続、commit・snapshot、受理・検証・引継ぎで意味を変えない方針を
既に要求していた。ADR-0057 も Git の確定一覧を後工程で使用すると記載していた。
それでも通常レビューの準備で元基点と出力基点を混同したため、
方針の記載と、各遷移で実装が満たす条件を照合する作業を分ける必要がある。

| 分類 | 確認した反例 | 今回の ADR 改善 |
| --- | --- | --- |
| 証拠の意味の変化 | RC7 の全変更確定から PR #263 の通常 Reviewer 準備へ渡すと、A→T が B→T に変わる | A/B/T/P/R と再現・範囲照合を分けた P1〜P7 |
| 出典・停止地点の限定 | RC3 は Coder、RC8 は持込み未準備 Reviewer、RC10 は準備済み、RC11 は正式停止済み。通常受理 Coder の未開始 Reviewer は PR #263 で補う | G1〜G5 で別経路の許可を流用しない。R1〜R10 で隣接状態を比較 |
| 遷移間の証拠失効 | PR #263 の独立レビューが取消後の source receipt 再照合不足を検出 | E1〜E7 で正本と再照合点を分け、前段 PASS 後の欠落を反例にする |
| 時間・処理寿命の不整合 | RC12 の旧／新期限矛盾、RC13 の停止前延長と終端後続、PR #232 の非同期 context 早期取消 | deadline と状態を一つの「復旧可能」にまとめず、旧実行と後続を別に評価 |
| 認可と品質の混同 | RC15 の診断、RC16 の派生役割認可、旧契約の文書条件不足 | 観測・受入れ・発行・結果受理・品質・公開の判断を分離 |
| 操作案内・完了証拠の不足 | #203 の早期 close を訂正。`ready`／help の確認と保存状態からの後続準備を再確認 | 試験名だけでなく実際の操作・終点・公開版／ソース版を記録 |

これらは公開記録から確認した種類の異なる不足であり、単一の根本原因を実証した結果ではない。
「全 RC が組合せ試験不足で起きた」「当時その試験が存在しなかった」とは断定しない。
すべての過去候補の試験を再実行したり、実モデルの見逃し率を測定したりしていないためである。
一方、出典を一つに限定した取消条件が隣接経路には適用されなかったこと、
期限条件の同時要求が矛盾したこと、正式受理後の基点が変わったことには具体的な根拠がある。

## 決定表の維持と残る受入れ

[ADR-0071](adr/0071-preserve-accepted-coder-review-lineage.md)を判断条件の正本にし、
[確認記録](normal-reviewer-handoff-validation.md#決定表とテストの対応)に試験との対応を置く。
表を追加するだけでは不具合を防げない。変更した各境界について、
許可例、一条件を変えた拒否例、別出典の隣接経路、遷移間の証拠欠落を確認する。
到達した操作と拒否後の保存状態も独立レビューの対象にする。
未対応・未確認を ○ とせず、全直積試験や実運用受入れを主張しない。

本調査は文書と設計判断の改訂であり、新たな runtime、保存形式、汎用復旧、
Coder・Reviewer の追加実行、旧承認の変更、再配布を行わない。
既存の `v0.7.23` 修正、成功検証、失敗・停止・利用量を保持する。
運用機での通常レビュー再開は未実施のままである。
入力形式・全役割の一般化、実モデルの行動・費用改善は #90／#189／#196／#225、
全完了経路の品質証拠は #221、実行環境と観測能力は #220 の既存課題に残す。
この履歴監査や新しい表のマージだけを理由に、それらを閉じない。
