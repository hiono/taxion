# v0.7.0 の既知の制限

v0.7.0 は、承認 bundle、実行入口の検査、3つの gate、read-only lane、機械可読 report、ADR-0043 と最小限の文書を追加する。次の項目は実装しない。

## 実行基盤

- 一般的な DAG executor。lane は固定の4本で、Task 間の依存を並列実行しない。
- 動的な lane plugin。lane の追加は binary の更新で行う。
- retry scheduler。失敗した lane や role を自動で再試行しない。
- 高度な cache。lane と gate の結果を保存して再利用しない。
- UI。すべての操作は CLI で行う。

逐次 role packet lifecycle は明示承認した READY Task と bounded review Flow が対象となる。発行済み Dispatch の採用、未来の evidence の生成、repair / re-review の追加契約承認は代替しない。保存・検証と rollback の条件は [role handoff packet](role-handoff-packets.md)を参照。

## Task 単位の集計と再契約

Task の上限集計、budget gate、未起動 Dispatch の terminate-and-recontract は実装済み。`workflow evaluate` が Dispatch/session 数、nano-AIU、経過時間、repair/re-review の承認上限・消費・残量を表示する。usage が不明・不完全な場合、nano-AIU 残量は0とし `BUDGET_STOP` で次の実行を止める。実行中 session は usage event を観測した時点で ceiling を検査し、超過時は停止する。provider の別 account 残高、請求額の予測、currency 換算は行わない。

## report の接続

lane report と gate report は別の report である。v0.7.0 では contract gate report に lane 結果を埋め込まない。両方を別々に実行し、`executionGateOpen` と `verdict` を確認する。

## 承認の範囲

- confirmation token は確認用の digest であり、認証 token ではない。token の一致は人間の認証を意味しない。
- gate は承認、Dispatch の発行、公開を代行しない。
- publication gate は、保存済みの Task と Flow の状態だけを読む。remote の権限、認証、公開先の現在の状態は検証しない。
- 公開の承認と配送は別の操作であり、gate が `pass` でも公開要求が自動で作られるわけではない。

## legacy の扱い

- `verified-legacy` の Task は従来の検査で実行できる。bundle を要求しない。
- `invalid-or-ambiguous` の Task は修復まで拒否する。自動変換はない。
- Task の一括再承認はない。v0.7.1 は既存の READY Task 1件ずつに対する設定承認を `taxion task reauthorize --task TASK_ID` で追記する。Task 契約や state は変更しない。
- v0.7.2 の READY Task 再承認は、既存の intake confirmation decision に有効で一意な immutable proposal reference がある場合に限る。既存 bundle がその参照と異なる場合も拒否し、hash の自動 migration や承認の書換えは行わない。

## 診断と credential

- gate report、lane report、入口拒否の診断は credential らしい値を伏せる。伏せ字の対象は既知の pattern であり、すべての秘密を検出する保証はない。
- bundle は解決済みの credential 値を保存しない。選択した設定 tuple と field の出典、その digest を残す。
- 診断に Task の全文や設定値を含めない。

## 互換性

- 未知の `bundleVersion` または `canonicalizationVersion` は `invalid` として扱う。v0.7.1 の READY Task 再承認は canonicalization version 2 を使い、v0.7.0 はその bundle を拒否する。
- v0.6.x binary は追記された bundle を gate 判定に使わない。v0.7.1 の再承認後に v0.7.0 へ戻してもその bundle を検証できないため、再承認後は v0.7.1 以降を使う。
- rollback は binary の差し替えで行い、ledger を書き換えない。既存 ApprovalBundle を削除・置換して rollback する経路はない。

## v0.7.1 の候補

- lane 結果の gate report への埋め込み
- lane と gate の結果 cache
- 追加の lane と plugin 機構
- 高度な Task accounting analytics、provider 横断の billing 集計、利用量予測
- Task 状態・履歴に応じた一般化 recontract policy
- dashboard と長期履歴分析

これらは Issue に記録し、v0.7.0 の受入れ条件には含めない。
