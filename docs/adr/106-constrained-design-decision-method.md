# ADR-106: 制約付き最適化による設計判断の比較方法

Date: 2026-11-20

## Status

Accepted

## Context

複数の設計候補を比較するとき、名称や型の類似だけでは責務の欠落や権限境界の違いを見落とします。また、安全上の必須条件を単一スコアへ含めると、低コストや利便性で違反を相殺する危険があります。

## Decision

複数候補の重要な設計判断には、必須条件をハード制約とする制約付き比較を適用します。単一候補や単純な局所変更には数理最適化を強制しません。

1. 解決対象を責務、不変条件、利用者要求、運用要求へ分解します。
2. 候補ごとに責務の代替、分割、移行専用、廃止、未充足を識別します。
3. 認証・認可、秘密情報、データ整合性、人間承認、二重実行防止などをハード制約とします。
4. ハード制約を満たす候補の中で、必須責務の充足、責務の重複、移行コスト、運用複雑度を順に比較します。
5. 実装状態と証拠を区別し、未確認事項は未確認として残します。
6. 比較開始時に必要な証拠と終了条件を定め、結論を変え得る新しい情報がある場合だけ再評価します。

最適化結果は判断を支援します。必須条件の変更、リスク受容、不可逆操作の承認は権限を持つ人が決定します。

## Consequences

重要な設計比較を再現可能な根拠と終了条件に基づいて行います。問題定義と証拠収集のコストを考慮し、適用範囲を複数候補間の重要な判断に限定します。

## Relationship to other ADRs

ADR-101は候補実装の評価原則、ADR-500はハード制約となる権限境界、ADR-800は検証証拠の水準を定義します。
