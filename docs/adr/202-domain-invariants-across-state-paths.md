# ADR-202: ドメイン不変条件を生成・変更・保存・復元の全経路で強制する

Date: 2026-11-20

## Status

Accepted

## Context

判定関数が存在しても、状態変更がその判定を迂回できれば不変条件は守られません。Job、承認、実行、成果の整合性は、生成から復元までの状態変更経路で維持する必要があります。

## Decision

**ドメイン不変条件はドメインモデルの規範とし、状態を生成・変更・保存・復元するすべての該当経路で強制します。**

- 各不変条件は対象状態、前提条件、成立条件を定義します。
- 状態変更は、変更後の状態が不変条件を満たす場合に成立させます。
- 新規生成、状態遷移、永続化、外部入力、migration、backup / restore、recovery、再送、競合を対象経路として評価します。
- validatorは既存状態の検査、mutation gateは不正状態の生成防止を担います。必要な境界で両方を使用します。
- 検証不能または不整合の場合はfail-closedとし、部分的な状態変更を残しません。
- 正常系、違反系、拒否後の状態不変性をテストし、実際の入口と呼出し経路を確認します。

本決定はJob、Task、RoleExecution、承認、通信、Provider operation、Worktree、成果、証拠、利用量および今後追加するドメインモデルに適用します。

## Consequences

不変条件の定義、強制境界、テストを対応付けます。判定関数や一部テストの存在だけで全経路への適用完了とはみなしません。

## Relationship to other ADRs

ADR-201はJobAggregateとCommand境界、ADR-300は通信、ADR-408はWorktree、ADR-500は権限と禁止副作用を定義します。各ADRは固有の不変条件と強制境界を具体化します。
