# ADR-0067: 次の改善を対象に結び付いた品質証拠から進める

Date: 2026-11-03

## Status

Accepted

## Context

v0.7.21 の正式公開と #201 / #248 の受入れを完了した。
次の改善を、Issue の番号順や閉じやすさだけで選ぶと、
未確認の完了を増やしたり、実行経路を広げてから検証不足を調べ直したりする。
既存の優先度、具体的な利用上の阻害、安全性、他の改善への効果、
必要な権限・外部環境、完了までの費用を区別して順番を決める。

外部側では保存済み成果の再利用と独立レビューが成功した一方、
旧契約の文書整合条件不足で Taxion の品質ゲートが未達となった。
この結果は正常な拒否として保持する。ただし `ready` の新規契約の例にも
必須の文書整合条件が含まれておらず、説明に従った実行が同じ不足を作り得た。
また、旧形式の結果は読めるが、現在の Controller による検証証拠と同一ではない。

## Decision

最初は #221 の品質証拠を整える。以降の実行基盤・課金・隔離の改善でも、
対象と必須検証を照合して完了を判定できるようにするためである。
次に #231 の応答前停止と診断を調べ、取得できる証拠と利用資格を
#234 の利用枠別判断へ接続する。課金方式を変えて障害を隠す順序は採らない。
認証情報の分離と独立実行環境は高優先度を維持する。
これは既知の重大な脆弱性を後回しにする判断ではなく、
そのような具体的な障害が確認された場合は順番を見直す。

順番と全未完了 Issue の分類は[ロードマップ](../roadmap.md#次に進める順番)に置く。
親 #220 は共通の受入れ管理であり、子 Issue 全件を一括実装する作業にはしない。
Issue の延期、外部環境待ち、未観測を、要求の削除や完了へ変換しない。
この判断自体は追加モデル、提供元変更、外部操作、リリースを承認しない。

### #221 の品質証拠

現在の命令形式では、保存グラフの検査が全承認済みコマンド、
実行時刻、同じ SHA / tree と作業場所の検証証拠、独立 Reviewer、
全受入れ条件の証拠付き合格を照合する。これを別の判定器へ複製しない。
評価は同じグラフ検査を使い、`targetSha` / `targetTreeSha` で照合対象を表示する。
実行・公開ゲートも評価の不足理由を伝え、文書条件不足を対象不一致だけのように説明しない。

命令形式4より前の成功結果は、Controller による検証・Git 証拠を
必須にしていなかった。読取り互換性を保ち、結果や旧承認を変更せず、
これらだけでは `RECORDED_PASS` を返さない。記録された検証済み品質の判定を
厳しくする変更であり、旧実行の再送や自動移行は行わない。
不足を解消する場合も正式な新契約と必要な承認を使う。

新しい `ready` の契約例には、既存の必須文書整合条件を含める。
条件のない旧契約は遡及変更しない。`modelFree` の完了は利用者申告の記録であり、
Flow の検証済み品質や公開ゲートの代替にはしない。
Web の台帳参照も独立レビュー済みとの表示にはしない。

## Consequences

新しい CLI の例から同一対象の品質確認までを、実 Git・実コマンド・保存と
模擬実行基盤で確認できる。検証失敗、未実施、古い対象、不完全な受入れを拒否する。
模擬実行を実モデル・実ブラウザ・全構成の受入れと同一視しない。
必須のブラウザ確認も、承認した検証コマンドの保存証拠へ束縛するが、
テスト名や成功サマリーだけで意味上の十分性を保証しない。
対応能力の提供と実ブラウザ構成の受入れは #226 の未達条件を保持する。

検証した経路、既存証拠と限界は
[確認記録](../artifact-review-validation.md#対象に結び付いた品質完了issue-221)に対応付ける。
予算・期限に収まらない後続 Issue は開始せず、保存済み成果と順番を保持する。
